## 产品决策

| # | 问题 | 背景 | 决定（2026-10-27） | 状态 |
|---|---|---|---|---|
| Q1 | **跨月退款怎么算？** | 真实账单里有一笔火车票退款 ¥131.50（分两次到账：¥121 + ¥10.50），原来的购票在账单时间范围之前 | **算作本月支出减少**：记为负数支出，抵扣本月支出 | ✅ 已实现 |
| Q2 | **给朋友的转账、红包、群收款，算不算消费 / 收入？** | 真实微信账单里有 21 笔转账、5 笔群收款、若干红包；收入 ¥2,950.90 里很可能大部分是转账（比如生活费） | **先都算进去**，第 7 步做分类时单独分出「转账 / 人情」类 | ✅ 维持现状，分类时再细分 |
| Q3 | **整体界面什么时候改？** | 上传区太长等界面问题 | **功能做完后，第 11 步统一打磨** | ✅ 已排期 |
| Q5 | **分类怎么分？** | 原来的 10 个分类是开发时随手定的，不贴合大学生的消费 | **餐饮、零食饮品、购物、交通、娱乐、生活缴费、学习、医疗、社交、其他**。按「买了什么」分，不按「在哪买」分（京东买教材 → 学习）；奶茶零食从餐饮拆出；居住、通讯合并为生活缴费；转账、红包、AA 叫「社交」 | ✅ 已实现 |
| Q6 | **怎么衡量自动分类准不准？** | 只说「分类效果不错」没有说服力 | 从苏宇晨的真实账单随机抽 **100 笔支出**，由苏宇晨标注正确分类，作为评测集；写规则时不看真实账单，避免准确率虚高 | ✅ 已排期 |
| Q7 | **「生活缴费」包含哪些？** | 评测发现苏宇晨把洗衣机、电动车充电、充电宝都标成了「生活缴费」，但原来的定义只有话费、电费、水费 | **改名「生活服务」**：话费、水电、洗衣、充电、充电宝、快递等校园生活开销 | ✅ 已实现 |
| Q8 | **要不要照着评测结果补规则（规则 v2）？** | 照着评测集里分错的交易补规则，再用同一份评测集测，准确率会偏高（相当于看了答案再考试） | **先不补**：保留规则 v1 作为干净的基准，直接做第 8 步，用 AI 补规则认不出的部分 | ✅ 已决定 |
| Q9 | **两笔可疑标注** | 打车标成了购物、题库标成了娱乐 | **都改**：打车 → 交通，题库 → 学习。评测集也需要质量检查 | ✅ 已改 |
| Q10 | **「太宽泛」的规则要不要让给 AI？** | AI 评测后，「规则 + AI」剩下的错误大多是规则抢先分错了：「超市」→ 购物（其实是买零食）、「美团」→ 餐饮（其实是借充电宝）、「抖音」→ 购物（其实是团购吃饭）、支付宝分类「生活服务」→ 其他。纯 AI 在这些交易上反而是对的 | 待决定：把这类宽泛规则改成「交给 AI 判断」。注意：这是看了评测结果才想到的改法，改完再用同一份评测集测会偏乐观（Q8），需要用下个月的账单重新抽样验证 | ❓ 待决定 |
| Q11 | **代付、借钱这类转账算不算支出？** | 苏宇晨看到「社交」有 ¥2,024，其中一笔 ¥1,525.75 的转账不是日常消费，把统计撑大了 | **可以手动标记「不计入」**：流水页明细里任何一笔都能勾选「不计入」，不再算进支出和收入，随时可以恢复。这笔 ¥1,525.75 已标记，总支出 ¥5,182.64 → ¥3,656.89 | ✅ 已实现 |
| Q12 | **「餐饮」和用户心里的「吃」不一样** | 苏宇晨看到餐饮才 ¥1,100 左右，以为花得更多。原因：奶茶零食单独算在「零食饮品」，国庆在家一周，部分转账可能是 AA 吃饭 | **方向 A：加「吃喝」大类**（餐饮 + 零食饮品）。流水页顶部显示「其中吃喝」，按分类汇总可以合并成大类。苏宇晨的真实账单：吃喝 1,346.17 元，占总支出约 37%。方向 B（转账逐笔确认用途）以后再说 | ✅ 已实现 |
| Q13 | **除了「吃喝」，还要什么大类？** | 两种思路：把小分类合并（生活出行、玩乐社交），或者换个角度分「必要 / 弹性」 | **加「必要 / 弹性」，放在看板里**。必要 = 餐饮、交通、生活服务、医疗、学习；弹性 = 零食饮品、购物、娱乐、社交；其他、未分类单独算。苏宇晨的真实账单：弹性 1,649.30 元（45%），比必要 1,566.07 元还多 | ✅ 已实现 |
| Q14 | **「问一问」找不到本地小店怎么办？** | 问「奶茶花了多少」时，AI 只能猜常见品牌名（蜜雪、喜茶……），苏宇晨常去的本地奶茶店它不知道，所以找不到 | 苏宇晨反馈「看不到奶茶花了多少钱」→ **让 AI 从账单里的商家名中挑相关的店**（只发商家名和商品名，不发金额、时间，不发转账对象），页面上有开关可以关掉，答案下面列出 AI 挑了哪些店。真实账单：本月奶茶从「找不到」变成 157.54 元、13 笔（找到了外卖里的「爷爷不泡茶」）；打车 + 共享单车从 2 笔变成 26 笔。已知不足：AI 会多挑一点（把 luckin 咖啡算成奶茶、把公交算成打车），所以列出挑中的店让用户自己判断 | ✅ 已实现 |
| Q15 | **「假期」要不要包括寒暑假？** | 法定节假日能自动判断；寒暑假每个学校不一样，要用户自己提供日期 | **只用法定节假日** | ✅ 已决定 |
| Q4 | **手动改的分类要不要永久保存？** | 现在改的分类只保存在这一次打开的网页里：刷新页面或重新导入账单，就会丢失 | **保存**：按每一笔交易的编号，把手动改的分类和「不计入」标记存在 private/手动修改.json（不上传，只存编号和改了什么，不存交易内容），重新导入时自动套用 | ✅ 已实现（随 Q11 一起做） |

| # | 问题 | 修复 |
